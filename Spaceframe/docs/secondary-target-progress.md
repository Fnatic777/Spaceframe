# SDD ledger - plan: Spaceframe docs\2026-11-18-secondary-target-plan.md

Probe findings used (STProbe, run in game by the user on 2026-11-18)
- Task 0: Ruling: with several targets listed, a weapon that reaches more than one fires at the first-listed one (one sample, test came out inconclusive by geometry) - so the list is kept as [main, secondaries...] and the main target keeps the weapons that reach it - cost if wrong: main target gets less fire than without the module; the first-listed rule is checked in game with Debug 1.
- Task 0: Ruling: SetSingleFire(0) on the ship's own weapon property removes the "one target at a time" restriction (simul:1) and is per ship (not shared with other ships of the class) - cost if wrong: an enemy of the same class would also fire at several targets; fallback of design section 12 (lift only while the group fires).
- Task 0: Ruling: releasing the fire key makes the game call StopFiring and empty the whole target list; the module re-adds the secondaries (key event handler plus the Interval cycle as safety net) - cost if wrong: a gap of up to one Interval without secondary fire after each key release.
- Task 0: Ruling: PulseWeapon.CanHitTarget is unusable for the reach test (point/vector arguments unclear, TypeError with a ship), so all pulse weapons count as free - cost if wrong: pulse weapons that reach the main target may be sent to secondaries by the game; the list order still keeps the main target first.
- Task 0: Ruling: the MANUAL probe (key held with single fire lifted) is inconclusive: three rounds gave onB:0 with B listed and in reach, but A also showed onA:0 in the last two, so the probe cannot tell if the game fires only at the main target while the key is held - the module is built on the list approach and the real test is the module itself in game with Debug - cost if wrong: manual fire gets no secondaries; then re-assert StartFiring(secondary) + SetForceUpdate(1) after the key event.

Task 1: Ruling: the module timer calls Cycle (the same function the key handler uses), registered only while the player's ship has the tech, and every handler/timer added in Start is removed in Stop with the same triple - cost if wrong: duplicate cycles or a leftover timer in a second Quick Battle.
Task 1: Ruling: Ships.py value is a bit sum (1 phaser, 2 torpedo, 4 pulse), Def = Config Weapons (7), 0 = off; the bit 2 is accepted but does nothing until phase 2 - cost if wrong: the user sees torpedoes not used by a ship set to 7.
Task 2: Ruling: single fire is restored only with the ship live (looked up by ID, never a stored proxy), writing back the original value read (never forced to 1); if the ship is gone the record is just forgotten - cost if wrong: a ship keeps single fire at 0 after the module stops (only possible while the ship lives).
Task 2: Ruling: Stop() touches no ship (battle end destroys them, see learned.md); it only removes handlers and timers and forgets the records - cost if wrong: a ship alive after Stop keeps single fire lifted until the next battle.
Task 3: Ruling: the range filter for candidates is measured from the ship (bank-to-target distance minus nothing extra, SecondaryRange percent of the phaser's full-damage range), limited to the MaxCandidates nearest live, uncloaked enemies other than the main target - cost if wrong: a candidate slightly out of reach is listed and simply gets no fire.
Task 3: Ruling: only mission enemies are candidates (never friendly or neutral), using the AutoFire helpers imported from its module; if the import fails the module disables itself - cost if wrong: module silently off, shown by Debug.
Task 4: Ruling: OnFireKey only forgets the module's record of what it added (the game already emptied the list on release) and the next Cycle re-adds the secondaries once - cost if wrong: secondaries appear up to one Interval late after a key press.
Task 4: Ruling: single fire stays lifted until the player changes ship, the tech is lost or the module stops with the ship live - not re-restored every time the group stops firing - cost if wrong: if the property turns out shared by class, enemies of the same class keep the lifted value; then switch to lift only while the group fires.
Task 5: Ruling: README (EN/ES/PT) documents torpedoes (bit 2) as not yet active (phase 2) and Secondary Target v0.1 in the header - cost if wrong: none, text only.
Audit fix (supersedes the Task 4 single-fire ruling): Ruling: single fire is lifted per group only while the group has at least one secondary to shoot at, and restored per group (RestoreGroup, only if currently lifted, so no flip-flop every Interval) when the wanted list and the record are empty, the group stops firing or the main target leaves its list; Cycle restores the whole ship and removes the added secondaries when the main target is gone or not an enemy, the AutoFire helpers are unavailable, alert drops, cloak, the ship changes or the tech is lost - cost if wrong: if the engine needs single fire already lifted before StartFiring(secondary), the first secondary is added one Interval later (lift happens in the same cycle, before the add, so expected none).
PhaserPerTarget: Ruling: with single fire lifted by the module, each target (main included) gets at most one firing phaser bank: every Cycle LimitPerTarget groups the firing banks by GetTargetID, keeps the one with the highest charge (tie: the one kept last cycle, stored by weapon index) and calls SetFiring(0) on the others (about 2 s hold, they refire later); runs for phaser groups only, never in vanilla single-fire mode, never for pulse; Config PhaserPerTarget 1/0; the kept map is forgotten when the group's single fire is restored - cost if wrong: beams may flicker; user to judge in game (the held bank may also refire after the hold and be held again each cycle).
PhaserPerTarget: Ruling (supersedes SetFiring(0)): hold extra phaser banks with Weapon.StopFiring() instead of SetFiring(0), because in game SetFiring(0) on a firing bank left the beam frozen in space as a static line (gone with PhaserPerTarget = 0); the engine refires a stopped bank about 0.25 s later while its target is in the list, so the hold is renewed every Cycle; default PhaserPerTarget stays 0 (experimental) - cost if wrong: StopFiring may also leave artifacts or let the bank restart every cycle, so beams may flicker.
PhaserPerTarget: Ruling: the holds are renewed by a second Timer (FastTimer, LimitInterval, default 0.05 s, module minimum 0.02) that only runs LimitPerTarget; it exists only while PhaserPerTarget > 0 and at least one phaser group is lifted by the module (g_dPhaser, set in MaintainGroup, cleaned by ForgetKept), is started or stopped by SyncFastTimer at the end of every Cycle, and is stopped by ForgetAll/Stop, restore and ship change; every tick looks the player up by ID, and a missing or dead/dying ship stops it; the slow Cycle keeps everything else - cost if wrong: if the engine still refires banks faster than LimitInterval the flicker stays; a very low LimitInterval may cost fps.
PhaserPerTarget: Ruling (audit fix): FastTick never stops its own timer; when the ship is gone/dying or nothing is left to limit it only sets bActive = 0 (MarkFastDead), keeping g_pFastTimer and its process intact while the callback still runs; the next SyncFastTimer (slow Cycle, other process) calls StopFastTimer, and StartFastTimer treats a bActive 0 timer as dead and replaces it - cost if wrong: a dead timer lives up to one Interval longer (harmless, its Update returns at once); if the engine still faults, drop the fast timer and fold LimitPerTarget into the slow Cycle.
PhaserPerTarget: Ruling: HoldMode 0 = StopFiring only; HoldMode 1 (EXPERIMENTAL) = StopFiring then SetFiring(0) on the same bank, so the beam is ended before the disable; the module never calls SetFiring(1) to undo it (it could start a bank the player had stopped) and lets the ~2 s hold expire by itself, also on restore or when the feature turns off - cost if wrong: a bank may stay off up to ~2 s after the lift is restored, or SetFiring(0) may still freeze a beam in space (then use HoldMode 0).
PhaserPerTarget: Ruling: HoldMode 1 is obsolete (exe analysis: same as 0). HoldMode 2 (EXPERIMENTAL, default stays 0) = StopFiring once, then the bank's EnergyWeaponProperty MinFiringCharge is raised to GetMaxCharge()+1 so the engine's 0.33 s TryFire retry always fails (no flicker, bank keeps recharging); the original value is recorded per (ship ID, group, bank index) before the change and written back, ship looked up fresh by ID (dying still restored, None just forgotten), on every release path (becomes kept bank, target no longer has 2+ wanting banks, single-fire restored, feature off, ship change/tech lost/no alert/main gone/cloak/dying, HoldSafety sweep), followed by one SetForceUpdate(1) per group. HoldHysteresis (1.0 s game time) blocks re-hold after a release and release/swap soon after a hold (forced releases ignore it). No fast timer in mode 2. Stop() restores nothing on purpose (ships are being destroyed). AutoFire's PhaserMinCharge is independent and untouched - cost if wrong: banks stay mute until the value is restored; user must restart the battle.
PhaserPerTarget: Ruling: PhaserPerTarget (StopFiring/SetFiring/MinFiringCharge hold, fast timer) removed - reactive cut after the engine already fired cannot avoid burst and flicker; a real fix needs an engine-side change (stbc.exe single-fire rule) - cost if wrong: one-bank-per-target is lost until the engine change. The earlier PhaserPerTarget rulings above are historical (options PhaserPerTarget, LimitInterval, HoldMode, HoldHysteresis, HoldSafety no longer exist).
Toggle: Ruling: Toggle + single fire lifted for as long as the toggle is ON (instead of only while a secondary is wanted) - the user wants the restriction off whenever the feature is on; cost if wrong: manual single-fire behavior changes on every ship with the tech while ON; mitigated by the toggle. Default ToggleKey J (all other letters but k/o are bound by vanilla BC, k/o by STProbe); StartEnabled 1.
- Ruling: Single fire is lifted on phaser groups only; pulse groups keep their original setting (user: a Defiant fires its 4 cannons together, a single-fire pulse must stay single) - cost if wrong: single-fire pulse weapons would not share targets across banks.
- Ruling: Torpedoes use the target list like phasers (confirmed by STProbe MULTI_TORP on a Galaxy DN: forward tubes at A, aft tubes at B after them, one launch per 0.5 s per system in turn, no ET_CANT_FIRE); tube arc = fixed +-30 deg cone via TorpedoTube.IsInArc(worldPoint) (TORPARC probe 12/12); free tube = main not in its arc, wanted = a free tube has the candidate in arc, no readiness filter; torpedo single fire left as the ship defines it (never lifted); option SecondaryTorpedoMinSolution replaced by SecondaryTorpedoRange (km, 0 = no limit, default 30); IsInArc failing counts the tube as not free - cost if wrong: secondaries wait behind the main target's launches (slower); an enemy within 30 km but outside every free tube's cone gets nothing; a single-fire torpedo group may still fire one tube at a time; raising/lowering the range needs a Config edit.
- Ruling: re-arm while the key is held applies to torpedo groups only (phasers/pulse keep firing on their own while the key is held); confirmed in game 2026-11-19 on a Galaxy DN (7 forward tubes at the main target, then 7 aft tubes at the secondary) - cost if wrong: a torpedo group with a different engine behavior is re-armed needlessly (bounded by the caps below).
- Ruling: re-arm caps 20 re-arms and 20 s per key press, same main target only, cleared on every release path, a stale record expires after 25 s - cost if wrong: a very long barrage stops re-arming until the key is pressed again; or a leftover record re-arms once after a release (harmless, expires).
- Ruling: torpedoes at secondary targets under AutoFire are deferred (future work): AutoFire taps groups with StartFiring/StopFiring, decides by the cone on the main target and fires whole volleys at it, so SecondaryTarget only sees the torpedo group for fractions of a second (3-enemy log, 2026-11-19); phasers and pulse are distributed normally - cost if wrong: AutoFire torpedoes always go to the main target of the moment; a manual key hold is needed for secondary torpedoes.
- Ruling: the on-screen Debug trace (banner shown after 3 s idle) is now secondary to the log file Spaceframe_debug.log (Debug = 1 + fileio exe patch; CPyDebug.Print is a no-op; 5000 lines per session, game-time stamps) - cost if wrong: without the fileio patch only the one 'log file unavailable' banner shows and Debug gives no trace; apply the patch or read the screen trace.
